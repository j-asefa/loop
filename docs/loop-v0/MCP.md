# MCP in Loop

Loop is a remote MCP host using the official TypeScript SDK 1.30, Streamable HTTP, real tools/resources/prompts discovery, and OAuth with PKCE or encrypted bearer/custom-header credentials. Datadog's curated default is US1 `https://mcp.datadoghq.com/v1/mcp`; other regions can replace the endpoint. Its documented API-key header names are `DD_API_KEY` and `DD_APPLICATION_KEY`. The user must supply authorized credentials. Tool catalog descriptors never authorize a call.

Permissions belong to one user and a selected agent. They are not shared across users or automatically inherited by every agent in a project. Project filing is independent of grants. Every tool call requires exact, expiring owner approval in V0, even when the server advertises `readOnlyHint`. Model calls, snapshot refreshes and MCP Apps calls use the same broker. The broker checks ownership, connection state, grants, schema and run state before dispatch. Disabling/revoking blocks future dispatch; a call already dispatched cannot necessarily be undone. Calls with uncertain outcomes are not replayed automatically.

DNS results are checked and pinned at socket resolution; public HTTPS only, no redirects, localhost, private/link-local/metadata addresses, URL credentials, or local stdio. Secrets stay encrypted at rest and on the server. Known credential values are redacted from tool results. OAuth state is single-use and owner-bound; the client, PKCE verifier and refreshed tokens are encrypted.

Native charts persist exact numeric samples, null gaps, source/tool, units, range, UTC timezone and capture time. The deterministic fixture uses the Datadog v1 metric query `series[].pointlist` shape; it is explicitly marked fixture data. This is **not yet a verified mapping of a live Datadog MCP tool response**. Live discovery and authorized result inspection remain a release gate; an unrecognized shape retains readable structured JSON. Generic `timeseries` and table schemas are validated. Refresh creates a new approved snapshot; saved results survive disconnect.

MCP Apps uses the official `AppBridge` and `PostMessageTransport`, with source-window checks, an owner-authorized HTML endpoint in a unique-origin `allow-scripts` iframe and a restrictive CSP. No same-origin access, cookies, external network, frames or forms are granted. App resources are bounded to 1 MiB; resource HTML and full tool results are omitted from feed listings and fetched only for the opened artifact. The initial arguments/result are delivered through the bridge; UI calls queue for the same approval path. Apps requiring external scripts or other capabilities fall back to the saved native/text result. No arbitrary HTML is injected into Loop's document. App-initiated calls report the queued run; completion is inspected in Running/Feed, rather than held in an indefinite iframe request.

Current sources checked 2026-09-23: [MCP SDK](https://ts.sdk.modelcontextprotocol.io/client/), [MCP Apps lifecycle](https://apps.extensions.modelcontextprotocol.io/api/documents/overview.html), [Datadog setup](https://docs.datadoghq.com/mcp_server/setup/), [Datadog tools](https://docs.datadoghq.com/mcp_server/tools/). Local SDK declarations also checked. No real credentials used in fixtures.
