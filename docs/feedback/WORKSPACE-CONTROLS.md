# Workspace controls

Feed starts with team/project filters and **Your agents**: three profile shortcuts with live status, **All agents** for the directory, and **New agent**. The gold **+** opens the message composer. Profile cards center the avatar, identity and message/edit controls above **Results**, **Messages**, **Files**, **Traces**, and **Your prompts**, in that order.

Agent profiles list every current team membership and distinguish **Manager** from **Member**. Each team offers **Message manager**, opening that team's manager conversation. **Message manager** is also visible beneath the workspace filters: with one team selected it opens the manager directly; with All teams or several selected, a compact chooser shows each team's manager. The selected team determines the conversation even when one agent manages multiple teams.

Running has one yellow badge at the top right of its navigation icon. It counts distinct agents actively executing in the selected team/project scope, including work still stopping after a pause request. Queued, waiting, paused, failed, and interrupted runs do not increase it. The badge disappears when no agents are running; attention items remain in **Needs you** and the feed's attention banner.

Double-tap **Feed** or **Running** in the bottom navigation to scroll that view to the top. Conversations keep the agent's avatar, name, provider, and model visible above the message scroller. Tap the avatar or name to open the agent's profile; an unsent conversation reply remains saved when navigating away.

Profiles and the labels above **Your agents** avatars show the specific model from the connection's harness catalog. Loop preserves the runtime's resolved model ID for aliases such as `opus`, using the same label in conversations and the model picker. Versions are never inferred from an alias; older runtimes that omit resolution retain their reported model name.

New agents start with an available single-word name, checked against all existing and previously reserved handles. Suggestions remain editable and stay unchanged while choosing a provider, model, or first prompt. A delayed suggestion never overwrites a name you have typed or cleared. Existing agent names are retained.

Opening a result or selecting **Reply** shows its author, formatted answer, and a reply box. Secondary actions are in **Result options**. Replies keep their draft and request identity after failure or closing the sheet, and collapse the sheet once accepted. They continue the result's conversation with its agent.

Each card in an agent's **Messages** tab also offers **Reply**. Its reply sheet quotes the selected update or final answer. Sending queues a follow-up with that message as explicit context in the same conversation. The accepted quote is saved with the prompt and retained through retries; later updates do not replace it. Expand **View quoted message** on the sent prompt to inspect that context. Public updates can be quoted; tool logs and other agents' or owners' messages cannot be used as reply targets.

The expanded message composer has an agent selector, a message box, and a compact attachment/model/send row. Project, agent-creation, and workflow controls live in their existing workspace screens. New messages inherit the recipient agent's project.

Select the model pill to open the combined model catalog from all connected harnesses and accounts, grouped by harness. The saved catalogs appear immediately while Loop refreshes them. Choosing a model saves that model and account on the agent for future runs; there is no separate Save step. Expand **Effort** inside the same picker to choose from that model's reported effort levels. Switching models resets effort to the runtime default. Loop uses reported capabilities rather than guessing unsupported levels. These controls are also in **Edit agent** and a conversation's **Change model** menu.

Settings are saved on the agent for future messages. Queued and active runs retain their original model, provider, and effort. Changing provider/account starts a fresh conversation for new messages, including team-manager messages. Previous conversations and their outputs remain available. Continuing a conversation tied to a previous account requires a new conversation; Loop does not silently move its history between accounts.

Choose **+** in either composer to open **Camera**, **Photos**, and **Files** options, or **Upload files** under a project's **Files** tab. Camera and photo options use the device's native picker. Uploads preserve original bytes, are visible in Files, and remain attached to the draft after a failed send or page reload. Once a message is accepted, the conversation retains the attachment and its download link. The current upload bounds are 25 MB per file and eight files per message. Removing a draft attachment leaves its saved file available in Files.

Agents can publish generated files with `loop_publish_file({path: "design/mockup.png", title: "Home screen"})`. The path is relative to the agent's workspace; files generated elsewhere must be copied there first. Broker and companion workspace reads are bounded to 25 MB and reject hidden files, credential paths, external symlinks and hardlinks. Existing HAPI workers retain their 10 MB/type bounds. Small files can also use `content` with `encoding: "utf8"` or `"base64"` and a filename as `title` (32,000 encoded characters), including API agents and direct app-server connections that do not expose a file workspace.

Published files appear immediately in the agent's **Files** tab and alongside its response. PNG, JPEG, WebP and GIF files have inline previews; all files have an original-byte download. Loop retains a private copy after the worker stops, including when the rest of the run fails. Retrying the same publication returns the same saved artifact. Result and message-reply headers open the agent's profile and show the model recorded for that run. Tables keep readable column widths inside a horizontal scroll area.

API connections send supported image formats (PNG, JPEG, WebP, GIF) and PDFs from the current user turn as native message attachments. Historical turns retain file references without repeatedly sending the bytes. Loop budgets encoded attachments at 20 MB per request and 5 MB per image; files above that budget remain available through `loop_read_file`, with an explicit note that they were not viewed inline. Other content is also read through `loop_read_file`. Subscription runtimes can retrieve original file chunks with that tool; binary content is returned as base64 for their native file tools. Companion sessions also receive paths to copies on the machine running Loop. Archiving hides an upload from Files without breaking references already accepted in conversations or retries. Reads remain restricted to files attached to that run's conversation, under the same workspace owner.

Public agent updates between commands are stored in the agent's **Messages** and **Traces** tabs and appear in the conversation between the prompt and final answer. **Messages** includes both intermediate updates and final answers, with pagination for the complete history. A final response keeps the streaming update's identity and uses its response timestamp so it appears above earlier updates. Conversation pages group queued runs in submission order and avoid displaying the streamed final response twice. **Running** previews show public messages, never command strings or tool results. The feed and **Results** contain final answers only. Native runs publish their final assistant response, rather than concatenating every progress update. Existing saved native progress is backfilled on upgrade, while edited artifacts remain intact. Traces group each run under a compact title, with the full prompt in **View prompt**. Public updates render as Markdown, while expandable tool logs retain their original text. Long prompts, URLs, and logs stay within the mobile viewport. This records the runtime's public messages; private reasoning is not exposed.

Claude account checks authenticate separately from optional catalog discovery. If the CLI cannot return a model catalog, authenticated accounts remain usable with the supported Sonnet, Opus, and Haiku aliases. Effort levels are offered only when the runtime reports them; command discovery still reports its own errors.

To remove a team, open the team selector, select that team, and choose **Delete team**. Confirmation removes its workspace grouping and clears its filter. Agents, conversations, files, and already-dispatched work are retained. Deleted teams are excluded from future manager routing.

Failed runs offer **View failure details** in Running. This opens only that run's saved traces, including the failed tool or runtime stage, available error code, and redacted explanation. Intermediate progress remains in Messages and Traces. Earlier runs may have only a generic error because older versions did not save the underlying cause; Loop identifies those missing details instead of inventing a reason. A tool call whose external outcome is unknown is not replayed automatically.

MCP tool requests default to a five-minute timeout, configurable with `LOOP_MCP_TOOL_TIMEOUT_MS` in the server environment (positive milliseconds). This applies to the SDK call and its HTTP transport. Cancelling a run also cancels its in-flight tool request; external side effects may already have happened. Provider limits and tool-server timeouts still apply.

## Verification

- Server tests cover upload ownership, original-byte downloads, UTF-8/base64 chunk access, draft request identity, provider payloads, team retention, model validation, and queued settings.
- Runtime fixtures check actual CLI/app-server framing, model/effort discovery, effort forwarding, and preservation of public progress. Migration tests cover existing records and edited artifacts.
- `npm run smoke:design` uses an isolated workspace in Chromium and WebKit. It checks the combined model catalog, automatic model/effort saving and recovery, attachment picker options, local error recovery, uploads and retries, draft persistence, conversation attachments, project Files, and cancelling/confirming team deletion, alongside the design/navigation regressions.
