# Unified laptop execution: implementation prompt

Implement PR #14 end to end. The user runs `loop`, selects OpenAI / Anthropic and native / Docker / both, pairs a phone once through cloudflared, then creates agents on the selected machine. Native means local harness execution with remote model inference.

Read progressively; do not load the entire repository at once.

1. **Integration baseline.** Read `package.json`, `src/cli.ts`, `src/workspace-host.ts`, `src/server/agent-runtime.ts`, and migrations. Reconcile current main with the HAPI branch, preserving queue ownership, approvals, cancellation, memory and existing companion behavior. Run typecheck and focused regression tests before proceeding.
2. **Launch and execution.** Read `src/native.ts`, `src/daemon.ts`, `runtime/broker.mjs`, `native/supervisor.mjs`, `native/worker.mjs`, and `src/server/hapi/`. Reuse companion lifecycle and HAPI contracts. Separate provider from execution location, persist defaults and keep conversation routing fixed. Support native paths and Docker project mappings without copying host credentials into images. Native children must inherit the user's Docker context.
3. **Pairing and tunnel.** Read `src/host.ts`, `src/state.ts`, `src/tunnel.ts`, and mobile connection storage. Tunnel only the authenticated gateway. Support supervised named tunnels and persist device trust across restarts without binding identity to a transient origin. Preserve revocation, expiry, origin and CSRF checks. Quick-tunnel address changes need an explicit rediscovery path; do not pretend persistence alone solves discovery.
4. **Portability and provisioning.** Read deployment setup, HAPI compatibility and process tracking. Generate private identities automatically; use platform-aware paths and identity-safe process teardown. Do not delete live PID records on a native host. Keep memory optional for first-run readiness.
5. **Acceptance.** Test provider/location selection, native and Docker concurrent sessions, approval/cancel/resume, project mapping, restart/revocation and tunnel recovery. Use deterministic fixtures where real provider credentials or Docker are unavailable; label those limits. Verify an authenticated provider turn and `docker ps` only when the environment supports them.
6. **Delivery.** Document commands and remaining manual sign-in steps. Run build/tests, inspect the final diff, commit and push to the existing PR #14 branch without force-pushing. Rewrite its title/body around the final implementation and actual validation. Never claim unperformed live acceptance checks.
